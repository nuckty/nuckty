# Глоссарий русской терминологии

Единый справочник для монорепозитория nuckty и его внешних потребителей. Каноническая форма — в левой колонке, варианты справа не используем. В коде — английский идентификатор, в прозе — русский термин; при первом появлении термина-заимствования рядом с русским даём английский идентификатор, дальше — как термин.

## Архитектура

| Термин | Значение | Не использовать |
|---|---|---|
| ядро | Пакет `@nuckty/core`. Знает только `nuckty build` и контракт `register(env)` | — |
| движок | Рендер-движок `nu`: применяет шаблоны и собирает страницу | — |
| расширение | Модуль с точкой входа `register(env)` из npm-пакета или локального файла; официальные пакеты используют `@nuckty/ext-*`. Родовой термин для пользовательских дополнений. Пять типов: pipeline, markdown, block, command, document | плагин¹ |
| remark-плагин | Внутренний механизм: MDAST-трансформация, которую markdown-расширение регистрирует через `env.markdown.use(...)`. Технический термин экосистемы remark, не пользовательский | — |
| `ext` | Поле в `config-nuckty.ts`, перечисляющее расширения | `plugins` |

## Типы расширений

| Термин | Точка входа | Что добавляет |
|---|---|---|
| pipeline-расширение | `env.pipeline` | Стадии сборки или хуки |
| markdown-расширение | `env.markdown` | Конструкции markdown-разметки |
| block-расширение | `env.levels` | Набор БЭМ-блоков как уровень |
| command-расширение | `env.commands` | Команду CLI |
| document-расширение | `env.document` | Документ BEMJSON из подготовленных движком данных |

## Модель данных и рендеринг

| Термин | Значение | Не использовать |
|---|---|---|
| BEMJSON | Внутреннее представление страницы: БЭМ-узлы, текст, вложенные массивы и пустые позиции | — |
| `BemNode` | Тип TypeScript одного узла дерева BEMJSON | — |
| `BEMTree` | Тип TypeScript дерева BEMJSON целиком: `BemNode`, текст, вложенные массивы и пустые позиции `null`/`undefined`/`false` | — |
| `Templates` | Коллекция деклараций шаблонов одной сборки, которую используют `block()` и движок | `Registry` |
| шаблоны nu.ts | Декларации шаблонов на TypeScript в файлах `.nu.ts`, которые применяет движок `nu` | шаблоны nu |
| блок | Переиспользуемая единица интерфейса, описывается файлом `.nu.ts` | — |
| обёртка | То, во что оборачивается контент: обёртка документа (`<html>`), обёртка страницы | обвязка², оболочка |
| собирать (страницу) | Действие движка: применяет шаблоны и выводит HTML | рендерить³ |
| `renderToBemJson` | Первый проход: дерево → разрешённое BEMJSON | — |
| `renderToHtml` | Второй проход: разрешённое дерево → минимальный HTML | — |
| переопределение | Своя версия блока на более позднем уровне вместо чужой | кастомизация |
| уровень | Каталог, где движок ищет файлы блоков. Порядок уровней задаёт приоритет | — |
| зависимости (deps) | Декларация того, какие блоки нужны странице. Точка входа — `*.bemdecl.js` | — |
| таргет | Один собираемый сайт из репозитория: свой язык, домен, выходной каталог. В коде — `target` | — |

## Результат сборки

| Термин | Значение | Не использовать |
|---|---|---|
| артефакт | Каталог `outDir` — готовый к публикации результат сборки | — |
| бандл | Сборка CSS или JS по декларации блоков бандла; набор для страницы выбирает обработчик документа | — |
| content-hash | Усечённый MD5 от содержимого → имя файла. Хэш растра включает оригинал и доступные варианты; при изменении данных меняется URL | — |
| манифест | `manifest.json` — реестр файлов артефакта с размерами и хэшами, кроме самого манифеста | — |
| `image-mapping.json` | Соответствие логических имён изображений хэшированным | — |
| минимизация | Выдача минимального HTML при сериализации: `renderToHtml` опускает необязательные закрывающие теги (например, `</li>` в поддерживаемых контекстах), кавычки вокруг однозначных значений атрибутов и значения булевых атрибутов. Отдельной стадии нет | сжатие |
| сжатие | Сжатие выбранных непустых файлов артефакта без потерь: Brotli Q11 в `brotli/`, Gzip 9 в `gzip/`, один к одному с оригиналом. Стадия `compression` | минимизация |

## Хостинг и отдача

| Термин | Значение | Не использовать |
|---|---|---|
| сервер | Целевая машина, отдающая сайт (nginx/Apache) | хост⁴ |
| хостинг | Класс хостинга (виртуальный, VPS, dedicated) | — |
| виртуальный хостинг | Хостинг, на котором несколько клиентов используют общие ресурсы сервера | shared-хостинг⁵ |
| генератор конфигурации | То, что собирает `nginx.conf` и `.htaccess` из данных | построитель |
| публиковать | Загружать артефакт на сервер. Команда — `nuckty deploy-ftp` | деплоить |

## Конвейер (pipeline)

| Термин | Значение | Не использовать |
|---|---|---|
| фаза | Одна из упорядоченных фаз конвейера: `clean → prepare → render → resolve → emit` | — |
| стадия | Именованный шаг внутри фазы (`sitemap`, `html`, `compression`, ...) | — |
| хук `before`/`after` | Код вокруг стадии | — |

## Документация

| Термин | Значение | Не использовать |
|---|---|---|
| конструкция markdown-разметки | Markdown-синтаксис, раскрывающийся в блок (`:::gallery`, `:::grid`). Связан с markdown-расширением | контентная конструкция⁶ |
| редактор | Инструмент, в котором пользователь правит текст или код; так называй его в подсказках и советах | среда разработки |
| намеренно | Сделано сознательно, не случайно | осознанный, сознательный |

## Принятые термины индустрии

Заимствования, которые устоялись и закреплены в коде или экосистеме. Используем как термины, не искореняем:

| Термин | Значение |
|---|---|
| контент | Текстовое наполнение страницы. Не «содержимое» (это про файлы) |
| рантайм | Среда выполнения (браузерный, серверный) |
| ассеты | Статические ресурсы сайта: стили, скрипты, изображения и файлы для скачивания |
| лог | Поток вывода программы («вывести в лог»). «Журнал» — для системных событий |
| релиз | Опубликованная версия пакета. «Выпуск» — в торжественном контексте |
| баг | Ошибка в коде |

## Глаголы — не калькировать

Глагол «рендерить» — только о проходе сериализации дерева в HTML. Про работу движка над страницей целиком — «собирать».

| Не использовать | Писать |
|---|---|
| эмитит | выводит |
| матчит | сопоставляет |
| резолвит | разрешает |
| деплоит | публикует |
| хардкодит | закладывает в код |
| коммитит / коммитится | передаёт в репозиторий / помещает под версию |
| форкает / форкать | ответвляет / создаёт ответвление |
| залогировать / логировать | выводит в лог / записывает в лог |

## Существительные — не калькировать

| Не использовать | Писать |
|---|---|
| фолбэк | запасной вариант |
| авторинг | написание / создание |
| UI-кит | набор компонентов |
| маппинг | соответствие / отображение |
| продакшн | продакшен / в продакшене |
| построитель (конфигурации) | генератор (конфигурации) |

## Написание

| Не использовать | Писать |
|---|---|
| хеш, кеш | хэш, кэш |

## Канцелярит — не использовать

Отглагольное существительное + «осуществляет/производит/выполняет» → один точный глагол.

| Не использовать | Писать |
|---|---|
| осуществляет запись | записывает |
| производит проверку | проверяет |
| выполняет генерацию | генерирует |
| производится сжатие | сжимается (или активный залог: «движок сжимает») |

## Склейки — не сращивать латиницу с кириллицей

Латинский токен не сращивают с русским словом через дефис. Исключение — санкционированные префиксы типов расширений: `block-`, `markdown-`, `pipeline-`, `command-`, `document-`, `remark-`.

| Не использовать | Писать |
|---|---|
| OS-байт | байт ОС |
| Inline-теги | встроенные теги |
| entity-экранирование | экранирование HTML-сущностей |
| tree-трансформация | преобразование дерева |
| dev-режим | режим разработки |
| Sitemap-модель | модель карты сайта |
| UI-компоненты | компоненты интерфейса |

## Фразовые кальки — не переводить дословно

| Не использовать | Писать |
|---|---|
| единый источник правды | единственное место, где заданы… |
| первоклассное значение | самостоятельный результат |
| мёртвый вес / груз | лишний вес артефакта |
| базовая гигиена | минимальный набор заголовков |
| давление масштаба | главная проблема роста |
| хлебные крошки бесплатно | движок строит их из того же дерева |

## Русская проза

Принцип: от сути к детали, действие вместо штампа.

1. Сначала идея, потом механизм.
2. Точные глаголы вместо общих слов и штампов; фраза читается как действие («доступны по одному адресу», не «живут по одному адресу»).
3. Образ вместо кальки и отглагольного существительного («не попадёт в продакшен случайно», не «страниц, ушедших в прод»).
4. Разбивай тяжёлые конструкции: длинные цепочки причастий — на естественные, через тире и вставки.
5. Не пересказывай: вторая мысль — новый образ, а не парафраз первой.
6. Ударение в конце предложения: замыкающее ставь последним.
7. Короткий хвост лучше длинного перечисления через запятые.
8. Знаки: не соединяй запятую с тире без причины; в «придаточное → указание» выбирай одно — глагол с запятой или тире без запятой. «, —» допустимо, только когда запятая закрывает свой оборот: «Всё, что нужно, — здесь».

## Примечания к исключениям

¹ «плагин» корректен только для remark-плагинов, сторонних (`eleventy-navigation`) и поля внешних библиотек. Родовой термин для `@nuckty/ext-*` — расширение.

² Глагол «обвязывать хуками» (how/pipeline, how/ext/pipeline) оставляем: другой смысл, «оборачивать хуками» звучит хуже.

³ «рендеринг» (существительное) и «рендерить» (о проходе сериализации) допустимы. Про работу движка над страницей целиком — «собирать».

⁴ «хост» как конфиг-поле со значением домена (`host: 'example.ru'`) корректен. Как отдающая машина — нет, пишем «сервер».

⁵ «shared-FTP», «shared dictionary» — технические термины, корректны.

⁶ «контентный» как прилагательное от «контент» (контентные зависимости, контентная логика, контентные редиректы) корректен. Только фиксированный оборот «контентная конструкция» заменяем на «конструкция markdown-разметки».
