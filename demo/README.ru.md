# nuckty-demo

Интерактивная витрина, собранная через публичный CLI nuckty. По пять страниц на русском и английском показывают Markdown/GFM, точные исходники примеров, галерею с лайтбоксом, сетку, типографику, живой редактор BEMJSON и реальные файлы сборки. Для светлой и тёмной темы используется указанный новый логотип; отдельный квадратный favicon подготовлен на основе его знака. `blocks/package.json` задаёт CommonJS для `.bemdecl.js`; шаблоны загружаются через декларацию бандла.

Редактор и настоящие примеры галереи и сетки доступны сразу на главной. Страницы разделов дают подробные инструкции и точные исходники.

## Локальная разработка

Нужен Node.js 24+. Зависимости `file:` указывают на соседние репозитории: сначала соберите ядро, затем root/gallery/grid, typography-ru и serve/validate/deploy-ftp, выполните здесь `npm ci` и `npm run build`. Русский результат — в `site/`, английский — в `site-en/`. Живой редактор включает чистые модули движка в браузерный бандл, поэтому нужны соседние исходники. Предпросмотр изолирован в iframe с sandbox.

При установленном nginx `npm run serve` запускает демо на `http://localhost:8092`, `npm run stop` останавливает его. Для сайта на `http://localhost:8091` запустите просмотр соседнего nuckty-site. Английский просмотр: `npm run serve:en`, адрес `http://localhost:8094`; остановка — `npm run stop:en`. Публичные домены — demo.nuckty.ru и demo.nuckty.com; для локальных ссылок между языками и сайтом используйте `npm run build:preview`. Контакт: vitaly@harisov.name.

## Проверка витрины

Выполните `npm run build`, `npm run lint`, `npm test` и `npm run validate`. Проверяются ссылки, якоря, ассеты, хэши, сжатые копии, галерея, типографика и sandbox. Для Nu Html Checker нужна Java. Локальное расширение `ext/showcase.ts` регистрирует конструкции showcase/example/playground и создаёт `build-files.txt` перед стадией manifest; снимок не включает сам себя и итоговый манифест.

## Проверка пакетов

При установленных зависимостях разработки запустите `npm_config_cache=/путь/к/npm-cache npm run test:package`. Скрипт собирает архивы tarball из копий исходников всех 11 пакетов — ядра и 10 расширений, — проверяет поля `main` и `types` и публичные декларации `register`, затем устанавливает только эти архивы во временный потребитель в каталоге с пробелами и Unicode. Его конфигурация подключает все расширения и собирает HTML, gallery и grid; после удаления копий исходников потребитель собирается повторно только из установленных пакетов. Скрипт не обращается к реестру или сети за пропущенными зависимостями npm cache и завершится с ошибкой, если кеш неполон.

Браузерный пример заранее собирается из настоящего движка, до удаления копий исходников. После успешной проверки временный каталог удаляется; при ошибке он сохраняется, а скрипт выводит его путь. Проверка не подтверждает публикацию пакетов в реестре и не проверяет работу serve, FTP или JVM в реальных условиях: во время сборки командные пакеты загружаются как расширения.

## Проверка чистой установки

Запустите `npm run test:clean-install` из этого каталога. Нужны исходники соседних пакетов и доступ к публичному npm registry. Скрипт копирует демо и его прямые пакетные зависимости в изолированный временный каталог, выполняет `npm ci` и `npm run build` для каждого соседнего пакета, затем выполняет те же команды для демо по его manifest и lockfile. Каталоги `node_modules`, `site` и `.build` исходной копии не используются для установки или сборки. При ошибке временная копия сохраняется, а скрипт выводит её путь; после успешной проверки она удаляется.
