# @nuckty/ext-command-serve

Локальная раздача собранного сайта через nginx с [сгенерированной конфигурацией](../../out/hosting.ru.md). Команды `nuckty serve` и `nuckty stop`.

## Тип

[command](../../how/ext/command.ru.md) — добавляет команды `serve` и `stop` через `env.commands`.

## Что делает

`nuckty serve [target] [--port N]`:

1. Выбирает [таргет](../../how/targets.ru.md) и проверяет его каталог [HTML](../../out/html.ru.md).
2. Находит `nginx` в `PATH`.
3. Записывает `.build/serve/<target>/nginx.conf` для этого артефакта и порта (8080 по умолчанию).
4. Запускает nginx на переднем плане с адресом `127.0.0.1`.

`nuckty stop [target]` читает `.build/serve/<target>/nginx.pid`, дважды проверяет команду и время запуска процесса и отправляет `kill -QUIT` только распознанному экземпляру. Без таргета команда останавливает просмотр всех объявленных таргетов. PID, конфигурация и журналы у каждого таргета свои, в `.build/serve/<target>/`, поэтому несколько таргетов можно раздавать одновременно на разных портах; очистка сборки сохраняет `.build/serve/`. Чужой, повторно использованный или некорректный PID приводит к отказу без сигнала.

Демон vnu завершает само расширение проверки после `nuckty validate`.

## Зачем отслеживать PID

На машине разработчика может работать другой nginx — системный или для других проектов. Поэтому `nuckty stop` использует сохранённый PID и проверяет идентичность процесса перед остановкой; при несовпадении отказывается его завершать.

## Локальная раздача

Конфигурация просмотра использует генератор ядра для маршрутизации, [сжатия](../../out/compression.ru.md) и выбора [изображений](../../out/images.ru.md). Она создаётся заново: изменения `nginx.conf` хуками сборки и правила Apache автоматически не переносятся. Проверка локального nginx не подтверждает настройку сервера в продакшене.

Без имени выбирается первый таргет. Порт — целое число от 1 до 65535. Команда работает на переднем плане; `nuckty stop` запускают из второго терминала в том же каталоге. Требуются инструменты POSIX; Windows без окружения POSIX не проверена.

## Только для разработки

Установите расширение как зависимость для разработки (`devDependency`) для локального просмотра. В CI оно также может использоваться для интеграционных проверок через настоящий nginx.

## Установка

Пример продолжает быстрый старт со стандартным обработчиком `@nuckty/ext-block-root`. Добавьте новое расширение в `ext` глобального `config/config-nuckty.ts`, сохранив остальные записи. Если обработчик документа собственный, оставьте его вместо `@nuckty/ext-block-root`.

Установите расширение из npm в распакованном [стартовом проекте](../../how/start.ru.md):

```bash
npm install --save-exact --save-dev @nuckty/ext-command-serve@1.0.0-rc.1
```

```ts
import { defineNucktyConfig } from '@nuckty/core';

export default defineNucktyConfig({
    targets: { main: { configDir: 'config/', outDir: 'site/' } },
    ext: ['@nuckty/ext-block-root', '@nuckty/ext-command-serve'],
});
```

Для работы требуется `nginx` в `PATH` (локально — через Homebrew или системную установку).
