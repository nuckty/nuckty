# @nuckty/ext-command-deploy-ftp

Публикация собранного артефакта на виртуальный [хостинг](../../out/hosting.ru.md) по FTP. Команда `nuckty deploy-ftp [target]` синхронизирует файлы по манифесту: отправляет на сервер только изменившиеся и удаляет лишние.

## Тип

[command](../../how/ext/command.ru.md) — добавляет команду `deploy-ftp` через `env.commands`.

## Что делает

Команда читает [manifest.json](../../out/assets.ru.md) из собранного артефакта, сравнивает манифест с файлами на сервере и передаёт только нужные изменения:

1. **Список файлов** — рекурсивный запрос `LIST` возвращает соответствие «путь → размер», по которому команда сверяет файлы.
2. **Манифест сервера** — без `--force` существующий `manifest.json` скачивается для сравнения хэшей. Если его нет, загружаются все локальные файлы; `--force` пропускает скачивание.
3. **Расчёт изменений** — команда находит новые, изменённые и удалённые файлы. Хэши сравниваются только при совпадении размеров.
4. **Защита от случайной очистки** — если доля удаляемых файлов превышает порог (по умолчанию 30%), команда останавливается и подсказывает `--allow-mass-delete`.
5. **Загрузка** — только изменившиеся файлы. Пассивный режим; по умолчанию явный FTPS, обычный FTP — только при `secure: false`. После каждой загрузки команда пробует сохранить время изменения через `MFMT`; отсутствие поддержки этой команды не останавливает публикацию.
6. **Удаление лишних файлов на сервере** — файлы, которых больше нет в артефакте, команда удаляет (`manifest.json` не трогает).
7. **Проверка и повтор** — после передачи команда снова выполняет `LIST` и при сбое повторяет загрузку.
8. **Манифест — последним** — перед первым изменением на сервере старый `manifest.json` удаляется, а новый загружается после того, как все файлы успешно переданы. Прерванный деплой не оставляет манифеста, поэтому следующий запуск загружает все файлы, а не доверяет устаревшим хэшам.

Перед соединением команда сверяет размер и MD5 каждого локального файла с манифестом. Перед последней отправкой манифеста она повторяет проверку и отклоняет изменившийся артефакт. Проверка на сервере использует `LIST` и размер; независимого подтверждения удалённого хеша нет. Во время публикации артефакт менять нельзя.

## Опции

```
nuckty deploy-ftp [target] [--force] [--allow-mass-delete] [--dry-run]
```

| Опция | Действие |
|---|---|
| `target` | Имя [таргета](../../how/targets.ru.md) из `config-nuckty.ts`. Без аргумента — первый таргет. |
| `--force` | Загрузить все локальные файлы без сравнения хэшей; защита от массового удаления продолжает действовать. |
| `--allow-mass-delete` | Разрешить удаление большего числа файлов на сервере, чем допускает защита. |
| `--dry-run` | Показать, что было бы загружено или удалено, без реальных действий. |

`--dry-run` подключается к серверу и читает его состояние, но не меняет файлы. Публикация не атомарна: переданные файлы могут остаться при последующей ошибке; итоговый манифест передаётся только после успешных операций.

## Аутентификация

Учётные данные берутся из `config/auth-ftp.json` или полного набора `FTP_HOST`, `FTP_USER`, `FTP_PASSWORD`, `FTP_PATH`; необязательны `FTP_PORT` и `FTP_SECURE`. Полный набор окружения имеет приоритет. Файл с секретами исключают из репозитория. Пример:

```json
{
    "host": "ftp.example.ru",
    "user": "user",
    "password": "...",
    "remote_path": "/public_html",
    "port": 21,
    "secure": true
}
```

В CI передавайте учётные данные через переменные окружения. Если используете `auth-ftp.json`, исключите его из контроля версий: файл содержит настоящие учётные данные.

По умолчанию используется FTPS с проверкой сертификата; ошибка TLS не вызывает переход к обычному FTP. `secure: false` или `FTP_SECURE=false` выбирает обычный FTP, который передаёт пароль в открытом виде; команда тогда выводит предупреждение. `port` по умолчанию 21 и должен быть целым числом от 1 до 65535. `progress: false` в `auth-ftp.json` отключает вывод хода публикации; при настройке через переменные окружения он выводится всегда.

## Ограничения целевого хостинга

Сервер должен предоставлять доступ по FTP или FTPS. SSH, rsync и Git на сервере не нужны. Расширение использует:

- **basic-ftp** — клиент с поддержкой пассивного режима и TLS (FTPS), без SSH.
- **MFMT** — восстановление времени изменения через команду FTP, а не через SSH.
- **Синхронизация по манифесту** — сравнение по хэшам вместо rsync.

Совместимость определяется протоколом передачи, а не классом сервера. Подробнее — в [решении о хостинге](../../why/hosting.ru.md).

## Установка

Пример продолжает быстрый старт со стандартным обработчиком `@nuckty/ext-block-root`. Добавьте новое расширение в `ext` глобального `config/config-nuckty.ts`, сохранив остальные записи. Если обработчик документа собственный, оставьте его вместо `@nuckty/ext-block-root`.

Установите расширение из npm в распакованном [стартовом проекте](../../how/start.ru.md):

```bash
npm install --save-exact @nuckty/ext-command-deploy-ftp@1.0.0-rc.3
```

```ts
import { defineNucktyConfig } from '@nuckty/core';

export default defineNucktyConfig({
    targets: { main: { configDir: 'config/', outDir: 'site/' } },
    ext: ['@nuckty/ext-block-root', '@nuckty/ext-command-deploy-ftp'],
});
```

Ядро не зависит от basic-ftp — зависимость живёт только в этом расширении.
